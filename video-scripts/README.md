# Brightfold video series: the visual guide

One series, one sample project. Together the episodes walk through **all of Brightfold**,
from the idea to winning the client, so a viewer who watches them in order has seen every
part of the project built.

- **Length:** every episode is **at least 5 minutes** (planned 6–8). Each one is a full walkthrough, not a teaser.
- **Where it lives:** YouTube first. Then paste the video ID into `src/lab/brightfold/path.ts`
  (`video.youtubeId`) and it appears on that step of `/lab/brightfold/path/`.
- **Rule:** every episode shows the real Brightfold files on screen (Figma, code, the live site, GA4).
  No talking over stock footage.

## The fixed shape of every episode (5–8 min)

| Time | Part | What's on screen |
|---|---|---|
| 0:00–0:30 | **Hook.** The mistake most people make at this step | One bad example vs. the Brightfold version |
| 0:30–1:30 | **Why it matters for conversion** | The path page, with this step highlighted |
| 1:30–2:00 | **Where we are in Brightfold** | The 13-chapter map, with this chapter lit up |
| 2:00–5:30 | **Build it** (the main part, 3–4 min) | Screen recording: Figma / code / Analytics, step by step |
| 5:30–6:30 | **The gap.** The thing most people skip here | A short checklist |
| 6:30–7:00 | **Recap and next episode** | What you have now + a preview of the next step |

## Workflow per episode

1. Build the Brightfold chapter first (the video records real work).
2. Write the script from this template (about 150 spoken words per minute, so 6 min ≈ 900 words).
3. Record your screen and voice. Add titles and diagrams in Remotion (code) or any editor.
4. Upload to YouTube: title, chapters (the timestamps above), link to the path page.
5. Add the video ID to `path.ts`, then push the site.
